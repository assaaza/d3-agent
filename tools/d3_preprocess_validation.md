# 범용 전처리 엔진 검증 — `d3_preprocess.py`

**검증일**: 2026-09-02
**검증 방법**: `test_d3_preprocess.py`로 기존 두 원본 데이터(건강, 1인가구)를 그대로 통과시켜, 이미 사람이 검토하고 확정한 결과(각 주제의 `data/processed/*/data_dictionary.md`)와 일치하는지 대조.

## 왜 이 검증이 필요했나

기존에는 주제마다 컬럼명을 코드에 하드코딩한 스크립트(`preprocess.py`, `preprocess_households.py`)를 따로 짰다. "이걸 하나로 합쳐도 될까?"라는 질문에 답하기 위해, 컬럼명을 전혀 모르는 범용 엔진을 만들고 — 새 주제가 아니라 이미 결과를 아는 기존 두 주제에 돌려서 같은 결론이 나오는지 확인하는 방식으로 검증했다.

## 1차 실행에서 발견된 버그 2건 (수정 완료)

범용화 과정에서 기존 스크립트에는 없던 문제가 실제로 나타났다 — 정확히 사용자가 걱정했던 "적용 안 되는 데이터가 생기면 어떻게 되나"의 실제 사례였다.

1. **이상치 탐지가 `year` 컬럼까지 검사함**: 1인가구 데이터는 조사 연도 간격이 불균등해서(2000, 2005, 2010, 2015, 2016~2025) `year` 자체를 IQR로 검사하면 "2000년, 2005년이 이상치"라는 무의미한 결과가 나옴. → 연도/ID처럼 식별자 역할을 하는 컬럼(`year`, `id`, `번호`, `date` 등)은 이상치 탐지 대상에서 제외하도록 수정.
2. **재구성(long→wide) 판단이 "불필요"와 "애매함"을 혼동함**: 1인가구 데이터는 pivot할 그룹 컬럼(성별 같은)이 아예 없는데, 숫자 컬럼이 여러 개(가구수, 총가구수, 비율)라는 이유만으로 "애매해서 보류"로 잘못 분류됨. → pivot 후보가 0개면 애초에 재구성이라는 개념이 성립하지 않으므로 "불필요"로 처리하도록 로직 수정 (애매함은 pivot 후보가 있는데 여러 개이거나 값 컬럼이 여러 개일 때만).

두 버그 모두 수정 후 재실행하여 아래처럼 기존 검증 결과와 일치함을 확인했다.

## 2차 실행 결과 — 기존 결과와 대조

| 항목 | 건강(성인 비만율) | 1인 가구 비율 | 기존 문서와 일치? |
|---|---|---|---|
| 상수 컬럼 개수 | 6개 | 4개 | ✅ (`data_dictionary.md`와 동일) |
| 숫자형 변환 | year, obesity_rate_pct | year, one_person_households, total_households, ratio_pct | ✅ |
| 결측치 | 없음 | 없음 | ✅ |
| 이상치 탐지 | 없음 | 2000년 행만 표시(Y), 삭제 안 함 | ✅ (기존 문서의 "2000년 15.5%, 표시만 함"과 동일) |
| 재구성(long→wide) | 적용됨 (`sex` 기준 피벗 → 남자/여자/전체 컬럼) | 불필요 (pivot 후보 없음) | ✅ (기존 "이미 tidy" 결론과 동일) |
| 결과 shape | 21행 × 4열 | 14행 × 6열(이상치 표시 컬럼 2개 포함) | ✅ 행 수 동일, 열 구성도 기존과 동일한 정보 포함 |

컬럼명을 전혀 하드코딩하지 않고도, 구조가 다른 두 데이터셋에서 사람이 수동으로 확정했던 결론과 동일한 결과를 재현했다.

## 이 엔진이 여전히 못 하는 것 (설계상 의도적으로 자동 처리 안 함)

- **숫자/텍스트가 섞인 컬럼**: 자동 변환하지 않고 `manual_review_needed`에 표시만 함.
- **pivot 후보가 2개 이상이거나, pivot은 1개인데 값 컬럼이 여러 개인 경우**: 어느 쪽으로 재구성할지 추측하지 않고 표시만 함.
- **index+pivot 조합이 유일하지 않은 경우**: 피벗하면 값이 덮어써질 위험이 있어 보류.
- **999, -1 같은 숫자형 결측 표시(sentinel value)**: 현재는 문자열 기반 결측 표기(공백, NA, "-" 등)만 인식함 — 다음 개선 후보로 남겨둠.

즉, "애매하면 자동으로 처리하지 않는다"는 원칙대로, 새로운 패턴의 데이터가 오면 조용히 틀리게 처리되는 대신 `manual_review_needed`에 이유와 함께 표시되고 나머지 안전한 항목만 자동 적용된다.

## 결론

두 주제 스크립트를 하나(`d3_preprocess.py`)로 합쳐도 기존과 동일한 결과를 낸다. 앞으로 새 주제를 진행할 때는 주제별 스크립트를 새로 짜지 않고 이 엔진을 그대로 재사용하면 된다.
